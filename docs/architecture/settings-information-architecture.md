# Settings & UX Information Architecture

## Context & Objectives

As Lina entered the Release Stabilization phase (0.2.3), the capabilities of the plugin (Desktop Producer + Mobile Companion model, embedding update lifecycle, provider policy, scheduler, backoff protection, SecretStorage boundaries) had matured significantly. However, exposing unnecessary technical complexity to general users creates friction and cognitive overhead.

The objective of **Phase 0.2.3.2 — Settings & UX Reorganization** is to structure all existing settings according to user needs without removing, simplifying, or breaking any underlying functionality.

### Core UX Principle

> **Show users what they need to operate Lina. Hide technical complexity until it is required.**

---

## 3-Tier Information Architecture

Lina settings are organized into three clear, progressive tiers:

```
Lina Settings
├── 1. Basic Settings (Everyday operational essentials)
├── 2. Advanced Settings (Specialized technical tuning)
└── 3. Diagnostics & Maintenance (Health inspection, cache management, recovery)
```

### 1. Basic Settings

The Basic tier presents everything the user needs for daily operation:

- **Lina Header:** Preserves identity, release version, development build information, and Buy Me a Coffee / support links.
- **Device Role Information:** Dynamically communicates the active device role and operational model:
  - *Desktop Producer:* `"Desktop Producer — This device maintains the index and generates embeddings."` / `"Desktop Producer — Este dispositivo mantém o índice e gera embeddings."`
  - *Mobile Companion:* `"Mobile Companion — This device consumes synchronized search data. Embeddings are generated by the Desktop Producer."` / `"Mobile Companion — Este dispositivo consome dados de pesquisa sincronizados. Os embeddings são gerados pelo Desktop Producer."`
- **Device Name:** Identification of the current device.
- **AI Configuration:** Core analysis provider, model selection, API key/credential configuration (when required), and connection test. Selecting the model remains firmly in Basic as part of normal user experience.
- **Semantic Search:** Semantic search toggle, embedding provider, embedding model, embedding update mode (`manual` vs `automatic-local-only`), credential management, and connection test.
- **Everyday Workspace Settings:** Inbox folder selection, automatic text index updates on file changes, excluded folders, YAML frontmatter suggestions toggle and tags inclusion, and interface language.
- **Support:** Support description and links.

### 2. Advanced Settings

The Advanced tier groups technical parameters and fine-tuning controls that general users rarely need to alter:

- **Analysis Fine-Tuning:** Custom base URL endpoint and connection timeout for AI analysis.
- **Embedding Fine-Tuning:** Custom base URL endpoint, batch size (note passages per batch), connection timeout, and embedding language.
- **Index Lifecycle Tuning:** Re-indexing on Obsidian startup and maximum inbox notes to analyze in batch mode.
- **Hybrid Search Tuning:** Balance slider weights between keyword text search (`hybridSearchTextWeight`) and semantic vector search (`hybridSearchSemanticWeight`).
- **Advanced YAML Properties:** Comma-separated list of YAML properties to generate and maximum suggested tags count.
- **Advanced Exclusions:** Path pattern exclusions and content term exclusions.

### 3. Diagnostics & Maintenance

The Diagnostics tier contains tools to verify index integrity, inspect sync data status, and manage performance caches:

- **Index Diagnostics:** Verification of synchronization on startup and debug update logging.
- **Search Acceleration Cache (formerly "Binary Copy"):**
  - High-speed in-memory optimization state.
  - Safe preference control (`prefer-binary` vs `jsonl`).
  - Automatic background maintenance toggle.
  - Diagnostic status breakdown with live aria feedback.
  - Explicit maintenance actions: Check cache, Create/update cache, Remove cache with destructive affordance and confirmation dialog.

## Producer vs Companion Device UX

Lina strictly differentiates the presentation between **Desktop Producer** and **Mobile Companion** devices:

1. **Role Notification:**
   - On Desktop, the device role identifies that this device maintains the index and generates embeddings.
   - On Mobile Companion, the device role states that this device consumes synchronized search data produced by the Desktop Producer.
2. **Companion Gating:**
   - Controls that are only valid for the Producer (such as embedding update mode configuration or generation triggers) are disabled or guarded on Companion devices.
   - In Companion mode, a clear notice is displayed:
     > **Companion mode active — This device uses search data generated by your Desktop Producer.**

## Architectural Invariants Preserved

1. **Zero Functionality Lost:** All 49 declarative setting definitions and actions are preserved with identical underlying data keys and behaviors.
2. **Deterministic Declarative Blueprint:** Blueprint structure cleanly models the 21 groups with zero schema migration or data structure breaks.
3. **Secret Storage Boundary:** API keys remain strictly in `app.secretStorage` per device; no secrets are exposed in diagnostics, blueprints, or logs.
4. **Mobile Safety:** Fully compatible with desktop and mobile runtimes; no desktop-only Node APIs or browser-incompatible dependencies introduced in the settings UI.
